# 14 — FATHER PROJECT REGISTRY / PORTFOLIO

**Status:** platform architecture / UI + data contract  
**Purpose:** make every FATHER project visible as a first-class production object linked to stages, documents, specialists, gates, budget, manufactured objects and Manufacturing Knowledge Base.

# 5. Project tabs

Each project workspace should expose:

## Overview
Current condition and project health.

## Stages
Production conveyor and stage nodes.

## Documents
All project artifacts grouped by stage.

## Objects
Products/agents/components/documents/data assets being manufactured.

## Decisions
DecisionRecord timeline.

## Risks
RiskFinding registry.

## Security
Security + DevSecOps Security view.

## Budget
Estimated / approved / actual cost.

## Traceability
Idea → requirement → architecture → component → test → evidence.

## Manufacturing Experience
Lessons, patterns, anti-patterns, defects, fixes, reuse records.

## History
Immutable event stream.

# 6. Project ↔ Manufacturing Knowledge Base

A project does not duplicate Manufacturing KB.

\`\`\`text
PROJECT
  ├── current state
  ├── current artifacts
  ├── current budget
  ├── current risks
  └── current objects

MANUFACTURING KB
  └── historical production experience generated by that project
\`\`\`

Relationship:

\`\`\`text
Project
  1 → N StageRun
  1 → N ArtifactVersion
  1 → N SpecialistAnalysis
  1 → N DecisionRecord
  1 → N GateResult
  1 → N RiskFinding
  1 → N CostRecord
  1 → N ManufacturedObject
  1 → N LessonLearned
\`\`\`

# 14. Canonical principle

\`\`\`text
PROJECT = CURRENT PRODUCTION STATE

MANUFACTURING KB = MEMORY OF HOW PRODUCTION HAPPENED

CATALOG = VERIFIED OUTPUTS THAT MAY BE REUSED
\`\`\`

The three must be linked but not collapsed into one store.

# Project Memory for approved projects

Every approved/released project must expose a compact **Project Memory**.

Project workspace adds:

- **Why We Built It This Way** — approved rationale digest;
- **Full History** — complete Manufacturing KB event/history view.

Completed projects remain visible in the portfolio with their approved memory, known limitations, last review and revisit triggers.

See `docs/15_FATHER_PROJECT_MEMORY.md`.
